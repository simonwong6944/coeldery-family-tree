老有樹 — 商戶平台規格（merchant_platform.md）
本文件記錄老有樹商戶平台嘅產品決定與規格，係商戶功能嘅「產品憲法」，與 product_decisions.md（用戶端）並列。標示：【核心】貫穿全局嘅定位／【已定】方向確認／【待定】需將來拍板／【願景】長遠 v2+ 方向。

---

〇、定位與商業模式【核心】

【核心】老有樹商戶平台定位為「本地商戶曝光平台」——連接香港本地商戶（如殯儀、醫療保健、飲食、家居服務等）與有照顧長者需求嘅家庭用戶，提供一個有溫度、有場景嘅曝光渠道。

【已定】收入來源：商戶付費上架 ＋ 商戶廣告（贊助排位）。平台不抽交易佣金，不介入商戶與用戶之間嘅交易，商戶與平台之間為直接廣告／上架費結算關係。

【已定】雙邊商業模式（與 product_decisions.md 第四節一致）：
- 用戶端：Freemium（基本免費 ＋ 增值收費）
- 商戶端：上架費 ＋ 廣告費（ad_tier 1/2）

【已定】v1 收費採線下收費：商戶透過線下渠道（如轉數快、支票、銀行轉帳）付費予平台；後端只記錄「誰付了、付哪個層級（tier）」，app 內無任何金流 UI。此設計避免 v1 過早承擔 PCI/金流合規成本，同時不影響功能驗證。

【已定】不涉用戶付款：用戶在 app 內只瀏覽商戶資訊，不作任何付款動作。商戶與用戶之間如有交易，屬線下自行安排，平台不介入、不留紀錄、不負責任何糾紛。

一、地區三級層級【已定】

老有樹商戶平台採三級地區層級，供用戶篩選「附近商戶」：

**第一級：區（District Group）**
| 區 |
|----|
| 港島 |
| 九龍 |
| 新界 |

**第二級：地區（District）**
每個「區」下設若干地區，例：
- 港島：中西區、灣仔、東區、南區
- 九龍：油尖旺、深水埗、九龍城、黃大仙、觀塘
- 新界：荃灣、葵青、沙田、大埔、北區、元朗、屯門、離島

（以上為示例，可隨商戶分佈調整，非硬性固定清單。）

**第三級：地標（Landmark）**
每個「地區」下設若干地標，用作「附近排序」嘅定位基準點。地標類型包括：
- 商場（如：荷里活廣場、荃灣廣場、沙田新城市廣場）
- 街市（如：長沙灣街市、大埔墟街市）
- 港鐵站（如：觀塘站、荃灣站、沙田站）
- 其他定位點（如：公立醫院、社區中心）

【已定】三級層級用途：
1. 用戶可按「區 → 地區 → 地標」逐層篩選，找附近商戶
2. 排序時以「距用戶選定地標距離」為自然排序基礎
3. 廣告排位（ad_tier 1/2）可在同一篩選結果內靠前，惟須標示「贊助」

【待定】地標之精確清單與 GPS 座標，待商戶入庫時逐步補充。

二、商戶分類【已定】

商戶設主分類（Category）及子篩選標籤（Sub-tags），結構如下。以下為 v1 示例，可隨商戶入庫擴充，非硬性固定。

| 主分類 | 子篩選標籤示例 |
|--------|--------------|
| 飲食 | 茶餐廳、酒樓（點心）、粥粉麵、素食、外賣到府、坐輪椅可進 |
| 醫療保健 | 西醫、中醫、牙醫、物理治療、職業治療、老人科、上門診療 |
| 家居服務 | 家居清潔、安老院舍、安老服務、居家護理、電器維修、改裝防跌 |
| 禮品與花藝 | 鮮花、盆栽、健康禮籃、賀年禮品、節日禮盒 |
| 殯儀與身後事 | 殯儀服務、法事、拜祭用品、墓地、靈灰龕位、遺體接送 |
| 長者日常 | 藥房、助聽器、輔具租借、接送服務、失智照護 |
| 其他 | （可擴充） |

【已定】子篩選標籤設計原則：
- 標籤係篩選工具，不作排名用途
- 一個商戶可同時有多個子標籤
- 標籤由平台維護，商戶不可自行新增（防止標籤污染）

三、上架與廣告兩層（核心）【核心】

老有樹商戶平台採「上架准入 ＋ 廣告排位」兩層結構，明確分離「能否出現」與「出現多前排」兩個問題。

### 3.1 is_listed：上架准入

【已定】`is_listed = 1`：商戶繳付上架費後，平台後端將其標記為 `is_listed = 1`，該商戶才會出現於 app 任何名單或搜尋結果。

【已定】`is_listed = 0`：商戶未繳付上架費，或上架費過期未續，即完全不存在於 app（不出現於任何名單、搜尋、推薦位）。對用戶而言，該商戶如同不存在。

【已定】上架費為進入平台嘅基本門檻，金額與週期（月費／年費）待定。

### 3.2 ad_tier：廣告層級（三級）

【已定】每個已上架（`is_listed = 1`）商戶均有 `ad_tier` 值，決定其在自然名單中嘅排位與曝光形式：

| ad_tier | 名稱 | 排位 | 顯示形式 | 贊助標示 |
|---------|------|------|---------|---------|
| 0 | 只上架 | 自然排位（以地標距離為準） | 文字名單 | 不需要 |
| 1 | 廣告（基礎） | 同地區內靠前 | 可加圖片、簡介 | 須標示「贊助」 |
| 2 | 廣告（置頂） | 贊助位（最前，獨立區塊） | 可加多圖、標語、優惠卡 | 須標示「贊助」 |

【已定】層級越高，曝光越大：ad_tier 2 > ad_tier 1 > ad_tier 0。

【核心】贊助位必須明確標示「贊助／Sponsored」，與自然名單清晰區分，維持用戶信任與合規。此原則不可妥協。

【已定】放棄「自然名單中性排序」舊原則：名單排序確實受廣告費影響（tier 1/2 靠前）；但凡非自然排序嘅位置，必須以「贊助」標示作補償，保障用戶知情。

### 3.3 贊助位佈局原則

【已定】搜尋結果頁面佈局：
1. 頂部「贊助區」：展示同地區內 ad_tier 2 商戶（獨立顯眼區塊，標示「贊助」）
2. 中間「廣告名單」：ad_tier 1 商戶靠前，有圖片（標示「贊助」）
3. 下方「自然名單」：ad_tier 0 商戶，按地標距離排序，無特別標示

【待定】同 tier 商戶之間嘅二級排序規則（如：評分、入庫時間、地標距離）。

四、優惠券（Coupon）概念【待定 / v1 概念層】

【已定（概念）】商戶可在平台掛載優惠券，吸引老有樹用戶光顧。優惠券係商戶額外付費或作為 ad_tier 1/2 附帶功能提供，平台提供展示位。

【已定（概念）】優惠券類型示例：
- 折扣券（如：出示 app 享九折）
- 免費試用（如：首次上門護理免費評估）
- 節慶優惠（如：重陽節特別優惠）

【已定】優惠券本身只作展示，核銷由商戶線下自行處理；平台 v1 不做核銷追蹤、使用記錄，不介入交易。

【待定】優惠券實作細節：DB schema、有效期顯示、一用即棄 vs 常設、商戶自助管理 UI 等，均待 v2 規劃。

五、與家庭圈／提醒卡嘅關係【核心】

### 5.1 商戶內容融入 feed 嘅原則

【已定】商戶廣告不自動插入家庭圈 feed（B4）——家庭圈係私人家族空間，強插廣告會破壞情感氛圍。

【待定】商戶內容如有機會出現於 feed，須以「情境相關推薦」形式呈現（如生日前推薦蛋糕店），且須有明確「贊助」標示，絕非自動混入家人動態。具體實作屬 v2+ 探討，v1 不做。

### 5.2 忌辰場合嚴格限制（沿用 product_decisions.md 現有規則）

【核心】忌辰場合之商業限制嚴格沿用 product_decisions.md [決策] 家庭日曆提醒呈現方式所載規則，逐字遵守，不得以任何商戶廣告邏輯覆蓋：

> **忌辰特別規則：永不彈出。只用安靜、莊重嘅 feed 提示，零商業意圖（只容許鮮花／拜祭意向，不可訂蛋糕／餐廳等）。**

【核心】具體禁止行為（商戶平台角度）：
- 忌辰提醒卡及忌辰事件詳情頁，不得出現任何商戶廣告、贊助位、推薦商戶連結
- 即使商戶主分類為「殯儀與身後事」或「禮品與花藝」，亦不得主動推送至忌辰場合——如用戶主動搜尋則另計
- 忌辰場合嘅「去安排」行動只限「獻上思念／送上鮮花」等莊重選項，嚴禁禮物、聚會、任何訂購按鈕

【已定】忌辰污染零容忍：商戶廣告系統嘅任何自動推薦邏輯，須在觸發前先判斷當前場合是否為忌辰；確認為忌辰場合則強制跳過一切商業內容。此為技術實作時嘅硬性守則。

六、Out of Scope（v1 不做）【已定】

以下功能明確不在 v1 範圍內，未獲明確決策前不得開始實作：

| 項目 | 原因 |
|------|------|
| App 內金流／用戶付款 | 金流合規成本高，v1 先驗功能；線下收費已足夠 |
| 商戶自助後台 UI | 平台營運初期人手管理，商戶資料由平台人員入庫 |
| 自動計費／續期提醒 | 依賴金流，v1 線下人手處理 |
| 跨區無限探索（全港不限地區瀏覽） | 平台定位「附近商戶」，無限探索稀釋在地情感價值 |
| 商戶評分／評論 | 需審核機制，防虛假評論，v1 複雜度過高 |
| 商戶 vs 用戶即時通訊 | 非核心功能，另開渠道成本高 |
| 優惠券核銷追蹤 | 依賴後台 UI，v1 線下核銷 |
| 跨平台商戶聯合廣告 | v2+ 探討 |

## 待定清單

以下細節需要之後拍板，在此集中記錄，避免遺漏：

1. **上架費金額與收費週期**：月費定年費？金額定價？設唔設試用期？
2. **ad_tier 1/2 費用**：各層收費金額？與上架費合計定獨立？
3. **同 tier 商戶二級排序**：相同 ad_tier 內，按評分？入庫時間？地標距離？隨機？
4. **地標精確清單與 GPS 座標**：隨商戶入庫逐步補充，定先建清單？
5. **商戶分類細化**：主分類與子標籤正式清單，需業務團隊確認。
6. **優惠券實作細節**：有效期顯示、一次性 vs 常設、DB schema。
7. **商戶資料入庫流程（v1 人手）**：由誰負責？格式？驗證標準？
8. **忌辰場合「用戶主動搜尋商戶」邊界**：用戶主動搜尋殯儀商戶時，是否豁免忌辰場合限制？定須另外處理？
9. **贊助標示之具體文案與樣式**：「贊助」定「Sponsored」定兩者並列？樣式參考？
