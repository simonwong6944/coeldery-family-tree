## Core Document v4

（CoEldery 85 家庭樹系統 — Core Document（最終版 v4）
一、目的
喺香港人口老化嘅背景下，愈嚟愈多長者面對子女移民、分散各地、少見面嘅現實；同時亦有愈嚟愈多人（唔論長幼）唔生育，將寵物視為至親家人。呢個系統嘅目的，係為長者提供一個私密、易用、有溫度嘅家庭回憶空間，讓佢哋能夠：睇到子孫及毛孩嘅近況與日常，唔會因為距離而失去連結；記錄與見證家族成長，尤其係新生嬰兒同新寵物嘅每月變化；記住並主動被提醒家庭嘅重要日子同節日，維繫親情儀式感；喺熟悉、安心嘅介面下，重新感受家庭嘅溫暖。

系統以「我」為中心呈現，操作極簡，專為唔熟悉科技嘅長者而設計。

二、定位
家庭樹係 CoEldery 85 生態嘅一部分，採用「app-within-app」架構（參考現有 CoLinkery 嘅模式）——係一個獨立嘅 sub-PWA，存在於 CoEldery 85 主 PWA 之內。必須先成為 CoEldery 85 會員先可以使用，藉此利用現有會員基礎確保安全性同時帶動增長。進入家庭樹後，會有自己嘅底部 tab bar，左上角設「← 老有卡 App」返回主程式嘅按鈕，右上角設 sub-app 識別標籤。透過會員邀請家人加入，自然生長，兼具拉新（growth）功能。

三、核心功能
3.1 家族樹 UI 與成員類型
分層橫掃呈現：每一代佔一橫帶，可左右滑動查看同層成員。大頭像、大字，適合長者。點選子女會自動聯動顯示佢嘅孫兒（center-focused／以「我」為中心嘅網絡呈現）。支援多家庭切換：若使用者屬於多個家庭（例如自己嘅家 + 配偶嘅家），提供家庭名稱下拉切換元件；若只屬單一家庭，元件自動隱藏，保持簡潔。高頻動作「加入家人」同「分享／邀請」放喺家庭樹主頁顯眼位置（大按鈕或頂部圖示），唔做成 tab。

關係模型（edge-based，邊為本）：同一個人可以屬於多個家庭、有多重身份（配偶、姻親），但永遠以「觀看者角度」呈現。

成員分兩種類型：

人成員：背後對應一個 CoEldery 85 會員帳號，有 SSO、可自行登入、上傳、like、留言。
寵物成員：一種無帳號、無 SSO 嘅被動成員，唔會自己登入或做動作，但擁有個人頁、相簿，可被人上傳相片同貼文。寵物唔屬於世代結構（唔會係邊個嘅仔或孫），透過一種新嘅 edge 類型「寵物—主人」掛喺主人（一位或多位人成員）之下／旁邊呈現為「XX 嘅寵物」，唔佔世代橫帶。任何成員都可以加入自己嘅寵物，邊個係主人邊個就可以加同管理。
3.2 相片／短影片（成員相簿 + 家庭圈）
基本配額：每位成員（人成員及寵物成員皆有）每月 5 張相片 + 2 條短片，影片長度上限 90 秒，作為私密相簿。

單次上傳、多處呈現（標籤機制）：上傳係單一動作，系統只儲存一份檔案，靠 metadata（標籤）決定喺邊度顯示，避免重複儲存。標籤包括「所屬成員」同「是否存入成員相簿」flag。邏輯：喺成員頁上傳 ⇒ 標記該成員 + 存入該成員相簿 + 同時出現喺家庭圈；一般分享（例如生日祝福圖）⇒ 唔標記成員相簿，只出現喺家庭圈；嬰兒或寵物成長相 ⇒ 標記該對象，存入成長相簿（+ 家庭圈 + 該對象成員相簿）。初版可根據「上傳位置」自動套用標籤，唔使長者手動揀。

家庭圈（Family Circle）：一個封閉、只限相連家人可見嘅動態流（類似 WeChat 朋友圈），將所有成員（人及寵物）嘅相片／影片／貼文以時間倒序排列，補足家庭樹（關係為本、逐個成員睇）嘅另一種「時間為本」入口。第一版功能：時間流列表（顯示發布者名稱、時間、媒體內容）；貼文類型支援純文字、相片（+可選文字）、影片；一鍵 like／心心；留言功能（forward／轉發唔做）；like 同留言繼承同媒體一樣嘅可見權限（只限相連家人）；有人 like 或留言時通知貼文擁有者；用戶可刪除自己嘅貼文同自己嘅留言。長者體驗：like 用單撳，打字留言另設一個畫面，唔想打字嘅人淨係 like 都得。

3.3 成長相簿（Growth Album）— 動態 tab
成長相簿係全 app 最有情感價值嘅賣點之一，適用於新生嬰兒同新寵物（好多人一樣想月月記錄幼犬幼貓嘅成長）。由於唔係每個家庭都有 BB 或新寵物，採用「動態 tab」機制：家庭冇登記新生嬰兒或新寵物 ⇒ 唔顯示成長相簿 tab，底部維持四個 tab；家庭有登記新生嬰兒或新寵物 ⇒ 底部導覽自動由四個增至五個，插入「成長相簿」tab。第一次出現時配一次性溫暖提示（例如「🎉 恭喜！你屋企多咗個新成員，我哋幫你開咗成長相簿，記錄佢每個月嘅成長 ❤️」）。一旦開啟，tab 永久保留，唔會因 BB 長大／寵物長大而消失。當有多個對象（可能有 BB 又有寵物）時，成長相簿頁頂部設選擇器揀「邊個 BB／邊隻寵物」。入口除咗 tab，亦同時放喺該對象嘅成員詳情頁。

配額：新生嬰兒／新寵物享獨立、額外嘅成長相簿配額，起始為每月 5 張相片 + 2 條短片（與成員相簿配額分開計）。此配額可透過推薦獎勵（有 BB 家庭）額外疊加（見 3.5）。

3.4 家庭重要日子（家庭日曆）+ 節日
由「生日功能」擴展而成，成為 app 核心情感引擎——將個 app 由「你要開先見到嘢」變成「佢主動提你去關心家人」。

日子來源分兩類：個人／家庭專屬日子——自動（人成員生日由會員資料出生日期自動生成）+ 手動（結婚週年、忌辰、入學／畢業里程碑、寵物生日、家庭自訂特別日子，可設每年重複）；公眾節日——系統內置、全平台共通（父親節、母親節、中秋、農曆新年、端午、重陽、聖誕、復活節等），節日臨近時全平台自動推送 + 帶入相關節日聚會商家。節日係可預測、每年重複、全民同步嘅聚會高峰，對商家係集中引流機會。

提前提醒：提前約一個月喺家庭圈出提示，家人可留言、發祝福。

因應日子類型配不同語氣同意向選項：生日（含寵物生日）⇒ 歡樂語氣 + 意向選項如訂蛋糕／訂餐廳／買禮物（寵物則寵物蛋糕／寵物用品／寵物 friendly 餐廳）；結婚週年（尤其金婚、銀婚）⇒ 溫馨儀式感 + 訂餐廳／訂鮮花；忌辰 ⇒ 莊重懷念語氣（「XX 忌辰快到，記得懷念」），絕不可出現訂蛋糕等不得體選項，意向可為訂鮮花／拜祭安排；里程碑 ⇒ 祝賀語氣；公眾節日 ⇒ 節日主題聚會意向。

三層結構（適用於所有重要日子及節日）：第一層（第一版做）——提醒 + 一鍵祝福／留言，純溫度、零商業、技術極簡。第二層（第一版做）——意向掣直接帶用戶去到家庭聚會相關商家列表 + 一鍵聯絡（見第四節）。第三層（future backlog）——真實訂購交易系統。

聚會確認後嘅家庭圈邀請卡：當聚會確認咗日期同地點，系統自動喺家庭圈生成一張「聚會邀請卡」，含場合、日期時間、商家名稱／地址／相片，及一鍵導航／致電。此卡對家人係清楚嘅聚會通知，對商家係額外免費曝光。

3.5 邀請與獎勵（增長引擎）
透過分享 QR code 或 WhatsApp 連結邀請家人加入。成功推薦定義：被推薦者開咗一棵新樹並加入咗第一個人成員（單純註冊唔算；寵物成員唔計入推薦有效性，因為寵物唔帶來新會員或增長），確保帶嚟真正會用家庭樹嘅活躍會員。

推薦獎勵（雙軌並存）：主獎勵——每成功推薦 5 位家人，解鎖 Type B 推薦獎勵券（商家優惠券），對所有長者有效（無論有冇 BB／寵物），折扣成本由商家承擔、唔使平台出錢；長者可喺清單自選想要嘅券。額外 bonus——若係有 BB 嘅家庭，同時額外送成長相簿配額（每 5 位成功推薦解鎖額外 5 張相 + 2 條片，自加入日起 6 個月有效、可累積）。

此設計令推薦系統、家庭樹增長、家庭聚會商家平台三者咬合成一個自我強化飛輪：長者為攞券而推薦家人 ⇒ 家庭樹增長 ⇒ 攞券去聚會平台幫襯商家 ⇒ 商家見到真實引流、更肯出券出廣告費 ⇒ 平台有更多更靚嘅券 ⇒ 長者更有動力推薦。

我的推薦頁：獨立頁面顯示邀請進度（例如「已邀請 3/5 位」）、已邀請家人狀態、剩餘優惠倒數，底部設「邀請更多」按鈕；分享頁只保留 QR／WhatsApp。

四、家庭聚會平台（Production 級完整廣告／引流平台，不含交易金流）
第一版完整開發並直接對用戶開放（由飲食業協會餐廳打頭陣，確保一開始就有真實商家內容）。

收費模式：向商家收廣告費／上架費／引流費 + 售賣營銷工具（限量優惠券曝光），唔抽佣、唔掂交易金流。本質係商家展示 + 引流平台，成交喺 app 之外發生。

用戶端：服務分類瀏覽（節日聚會、生日宴、蛋糕、鮮花、禮物、聚會場地、寵物相關服務等）；商家／服務展示頁（相片、介紹、地址、營業時間、電話、簡單服務內容）；由家庭重要日子及公眾節日直接跳入相關商家列表；接觸商家方式（不含交易）——一鍵打電話、一鍵 WhatsApp、一鍵睇地圖／導航。

優惠券系統（統一 coupon engine，兩個 type）：背後用同一套券系統，支援多種券類型，共用底層機制（發券、領取、WhatsApp 聯絡商家、商家自行核銷、記錄，全程唔涉平台金流）。第一版兩個 type：Type A 家庭聚會推廣券——商家買嚟做營銷、CoEldery 85 會員限量領取、限量製造稀缺感；Type B 推薦獎勵券——專為推薦獎勵而設、與聚會券唔同批、成功推薦解鎖後可喺清單自選。

優惠券雙動作流程：動作一領取（Claim）——記錄會員身份、商家、券別、時間，受限量控制；動作二一鍵 WhatsApp 確認預訂——訊息預填會員身份及券資訊，直接發送俾商家。平台掌握「領取」記錄，商家掌握「預訂確認」記錄，兩邊夾埋完成核銷。此雙動作亦提供最高質嘅引流證據（真實預訂 lead）。領取與確認之間嘅名額鎖定／釋放邏輯（例如領取後未確認 X 日自動釋放名額）待 spec 階段定義。券嘅核銷方式（coupon code／QR code 俾商家人手或簡單核銷頁確認）亦待 spec 定清楚。

商家端（雙檔上架）：商家自助上載資料 + 你哋審批（較平）；或你哋團隊代為上架（收 admin charge）。第一版需建俾商家自助上載嘅介面 + 俾團隊審批嘅後台。

引流數據：記錄邊個商家俾幾多人睇過、幾多人撳「打電話」／「WhatsApp」、幾多人領券。第一版功能建好，但屬內部用途，暫不使用，待數據成熟靚睇先作商業用途（同商家傾廣告費嘅硬證據）。

五、技術整合
採用 SSO（JWT）與 CoEldery 85 會員系統對接。透過 API 讀取會員資料，首次進入即自動建立根關係。CoEldery 85 係 PWA，支援 web-push、加到主畫面、離線快取、快速啟動；iOS 需加到主畫面後先支援 push，Android 限制較少。通知策略：第一版「必做」= 開啟時抓取嘅站內最新動態／家庭圈紅點提示；「想做」= PWA push 通知。Push 基建（manifest、service worker、權限）屬主程式，家庭樹模組只產生通知事件 + 一個簡單「開啟通知」提示 UI。

六、底部導覽（家庭樹 sub-app 內）— 動態 tab
採動態 tab 機制。基本四個 tab：家庭樹／家庭圈／家庭聚會／我的推薦。有新生嬰兒或新寵物時自動變五個：家庭樹／成長相簿／家庭圈／家庭聚會／我的推薦。原本一度存在嘅獨立「通知動態」tab 已併入家庭圈，通知改以紅點指示器呈現。左上角固定設「← 老有卡 App」返回主程式按鈕，右上角設 sub-app 識別標籤。

七、設計信念
極簡至上：大字、大按鈕、少雜訊。私密為先：內容只限相連家人可見，後端權限嚴格。溫度為魂：介面溫暖、安心，令長者用得舒服、用得開心；家庭嘅定義包容——子孫、姻親、以至毛孩，都係家人。

八、第一版明確不做（Out of Scope）
一、一切涉及金錢處理嘅功能（付款、金流、交易、抽佣、退款、發票、商家結算）——刻意永久劃出去嘅界線，唔止第一版。家庭聚會商業模式定為廣告／引流 + 售賣營銷工具，而非交易抽佣。二、預售券及平台通用券（涉及金流、退款、商家結算，平台通用券更可能觸及香港 SVF 儲值支付牌照監管）——入 future backlog，需專門法律 + 財務評估。券只做「商家自核銷、平台唔掂錢」模式。三、家庭重要日子第三層真實訂購交易（訂蛋糕／訂餐廳／訂鮮花／買禮物之真實下單付款）——第一版只做提醒 + 祝福 + 意向引流至商家。四、消費兌換額度機制（配額由後台管理調整，唔做自動消費換配額）。五、CoFilmery 繼承／AI 短劇模式（資料模型預留 hook）。六、智能關係計算（自動稱謂推算）。七、跨家庭深度導覽嘅完整體驗（只做用戶自己家庭之間切換，唔做無限世系探索）。八、複雜權限設定（只做簡易預設：直系相連家人可見）。九、家庭圈轉發／分享功能。十、商家自助後台嘅進階功能（第一版商家自助只做基本上載，進階管理日後先加）。

九、願景
讓每位長者透過家庭樹睇到家人同毛孩、見證成長、記住重要日子，重新感受家庭連結，並透過與家庭聚會生態嘅連動，令親情團聚變得更容易、更頻繁——成為一個私密回憶平台，同時驅動 CoEldery 85 生態嘅自然增長。）
